# NutriLife AI Assistant

A React and TypeScript prototype that uses Google's Gemini API to generate explanations of food and lifestyle products from text or an uploaded image. The project explores multimodal input, structured AI responses, and account-based analysis history.

[Hosted app](https://nutrilife-ai-assistant.vercel.app) · [Source walkthrough](#source-walkthrough) · [Local setup](#local-setup)

## Features in the source

- **Product analysis:** Accepts a product name, ingredient text, or an image and requests a letter grade, ingredient explanations, potential allergens, and alternative products.
- **Lifestyle planning:** Turns a list of regularly used products into a model-generated plan with prioritized swaps.
- **Recommendations:** Uses previously analyzed products, including those graded A or B, to request new product suggestions.
- **Accounts and history:** The `src/` application integrates Firebase email/password and Google sign-in, with product analyses and lifestyle plans stored in Firestore.

The grades and suggestions are generated by Gemini. They are not a validated nutritional scoring system or medical advice.

## Source walkthrough

The application lives in [`copy-of-nutrilife-ai(1)/`](<copy-of-nutrilife-ai(1)/>).

- [ProductAnalyzer.tsx](<copy-of-nutrilife-ai(1)/src/components/ProductAnalyzer.tsx>) handles text/image input, resizes images in the browser, and displays loading, error, and result states.
- [geminiService.ts](<copy-of-nutrilife-ai(1)/src/services/geminiService.ts>) defines the prompts and JSON response schemas for product analysis, lifestyle plans, and recommendations.
- [AuthContext.tsx](<copy-of-nutrilife-ai(1)/src/contexts/AuthContext.tsx>) manages Firebase sign-in state.
- [useHistory.ts](<copy-of-nutrilife-ai(1)/src/hooks/useHistory.ts>) reads and writes history in each user's Firestore document.
- [Dashboard.tsx](<copy-of-nutrilife-ai(1)/src/components/Dashboard.tsx>) brings together recent activity and recommendation requests.

## Project status

This is a prototype. A production build of the current application source completes, with warnings about a missing `/index.css` reference and bundle size. The hosted page responds, but sign-in, saved history, and live AI requests have not been verified end to end in this review.

Known limitations:

- `index.html` loads both `src/main.tsx` and the older `index.tsx`, which mount separate React applications into the same element. The older implementation uses browser storage; the `src/` implementation uses Firebase. These entry points need to be consolidated.
- Gemini calls run in the browser, and the build includes the configured API key. Moving these calls behind a server endpoint is a prerequisite for keeping that key private in a public deployment.
- Generated ingredient claims, grades, product images, and shopping URLs are not independently verified.
- The repository does not currently include automated tests or a dependency lockfile.

## Local setup

<details>
<summary>Prerequisites, configuration, and commands</summary>

Use Node.js 22 or newer and npm for the commands below. You will also need a Gemini API key and a Firebase project.

### 1. Install dependencies

```sh
git clone https://github.com/Zeph3737/Nutrilife-AI-Assistant.git
cd "Nutrilife-AI-Assistant/copy-of-nutrilife-ai(1)"
npm install
```

### 2. Configure Firebase

Register a Firebase web app, enable the Email/Password and Google authentication providers, and create a Cloud Firestore database. Configure the authentication domains for your local or hosted app.

The `src/` implementation stores history under `users/{userId}`. The following rules restrict each user document to its signed-in owner:

```text
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{userId} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
    }
  }
}
```

### 3. Provide environment variables

Create `.env.local` alongside `package.json` inside `copy-of-nutrilife-ai(1)/`, using values from your Gemini and Firebase projects:

```dotenv
API_KEY=your-gemini-api-key
VITE_FIREBASE_API_KEY=your-firebase-api-key
VITE_FIREBASE_AUTH_DOMAIN=your-firebase-auth-domain
VITE_FIREBASE_PROJECT_ID=your-firebase-project-id
VITE_FIREBASE_STORAGE_BUCKET=your-firebase-storage-bucket
VITE_FIREBASE_MESSAGING_SENDER_ID=your-firebase-messaging-sender-id
VITE_FIREBASE_APP_ID=your-firebase-app-id
```

Keep this file untracked and do not commit it. The current repository does not include a `.gitignore`.

### 4. Start the app

```sh
node --env-file=.env.local node_modules/vite/bin/vite.js
```

This explicitly loads the environment before Vite starts, because the current `vite.config.ts` reads `process.env` directly. Open the local URL printed by Vite. The duplicate entry points described above remain a known runtime issue.

### 5. Build and preview

```sh
node --env-file=.env.local node_modules/vite/bin/vite.js build
npm run preview
```

The package also defines `npm run dev` and `npm run build`; these can be used when the required variables are already present in the process environment.
